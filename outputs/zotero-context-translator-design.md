# Zotero 语境感知翻译插件设计规格

- 日期：2026-08-03
- 状态：待用户整体审阅
- 目标客户端：Windows 64 位 Zotero 9.0.*；首个验收版本为 Zotero 9.0.6
- 交付物：插件源码、自动化测试、可安装 `.xpi`、安装与使用说明、性能验收报告
- 插件名称：Zotero Context Translator
- 插件 ID：`zotero-context-translator@local`
- 首个版本：`0.1.0`
- Manifest 兼容范围：`strict_min_version: 9.0`，`strict_max_version: 9.0.*`

## 1. 产品目标

在 Zotero PDF 阅读器内提供结合论文上下文的单词、句子和段落翻译。插件自动取得论文标题、摘要、当前章节、相邻文本和本文术语，在用户主动点击翻译后调用 OpenAI-compatible API，并在选区附近的浮动窗口中显示结果。

插件的核心竞争力不是翻译按钮，而是：

1. 自动建立论文结构索引；
2. 稳定判断选区所属章节；
3. 在有限 token 预算内选择最相关的论文上下文；
4. 保持同一篇论文中的术语译法一致；
5. 不用隐藏 API 请求换取上述能力。

## 2. MVP 范围

### 2.1 包含

- Zotero 9.0.*、Windows 64 位；
- 带文本层的 PDF；
- 单词、句子和段落选择；
- OpenAI-compatible Chat Completions 接口；
- `Base URL`、`API Key`、`Model Name` 三项必填配置；
- 可配置目标语言，默认简体中文；
- 浮动翻译窗口；
- 本地自动提取标题、摘要、文本块、阅读顺序和章节层级；
- 本地章节索引、论文档案和术语表缓存；
- 流式响应、取消请求和明确错误提示；
- API 连接测试；
- 手动重新分析论文和清理缓存；
- 功能、准确性、稳定性及性能验收。

### 2.2 不包含

- Zotero 7/8 兼容；
- EPUB、网页快照和纯文本附件；
- Anthropic、Gemini 等原生协议；
- 本地模型管理；
- 全文向量数据库或 embedding RAG；
- 内置 OCR；
- 整篇论文一键全文翻译；
- 云端同步插件缓存；
- 默认持久保存每次完整翻译历史。

纯扫描 PDF 会被识别为“无文本层”，浮窗给出明确提示，不伪造章节或翻译结果。OCR 作为后续独立模块，不改变本设计的索引接口。

## 3. 已确认的交互

### 3.1 浮动窗口

1. 用户选中文本后，插件立即保存选区快照：附件 ID、文本、页码、矩形坐标和时间戳。
2. 选区附近立即出现完整浮动小窗，目标为 P95 不超过 100 ms。
3. 小窗默认显示“翻译”“解释术语”“复制原文”和关闭操作。
4. 用户点击“翻译”后，同一个窗口原位切换为加载状态；不转成固定右侧面板。
5. 结果仍在该浮窗显示；长内容只在窗口内部滚动，窗口可拖动。
6. 点击浮窗内按钮不得清除原选区。插件保存原始 selection 快照，并根据矩形坐标绘制临时视觉覆盖层。
7. 关闭浮窗、在正文创建新选区、切换附件或关闭阅读器时，旧选区才释放。
8. 一个阅读器实例同时只保留一个活动翻译浮窗，避免重叠和状态竞争。

浮窗按钮的 `pointerdown`/`mousedown` 处理需要阻止阅读器抢占焦点，但不能阻止键盘操作。窗口必须支持 Tab 导航、Escape 关闭、可见焦点和屏幕阅读器标签。

### 3.2 调用授权

- 选择文本本身不调用 API；
- 标题、摘要和章节结构的本地提取不调用 API；
- 只有用户在浮窗点击翻译或解释后才调用 API；
- 用户无需点击“分析论文”；第一次主动翻译时，模型在同一个响应中返回译文、论文档案和术语建议；
- 索引未完成时不阻止翻译，使用 Zotero 元数据和当前页邻近文本降级处理。

## 4. 总体架构

插件采用“后台索引通道”和“交互翻译通道”两条独立通道。

### 4.1 组件

| 组件 | 职责 |
|---|---|
| `PluginLifecycle` | 注册、卸载 Zotero 窗口和阅读器事件；清理资源 |
| `ReaderAdapter` | 适配 Zotero 9 阅读器事件，取得选区文本、附件及位置 |
| `SelectionSnapshotService` | 保存选区快照，维护临时高亮覆盖层 |
| `FloatingWindowController` | 管理浮窗状态、位置、拖动、焦点和取消操作 |
| `MetadataProvider` | 从附件父条目读取标题、摘要、作者、期刊等字段 |
| `PdfStructureExtractor` | 提取书签、页面文本块、坐标、字体特征和阅读顺序 |
| `HeadingDetector` | 根据书签、编号、版式和标题词典识别章节候选 |
| `DocumentIndexer` | 生成 `documentOrdinal`、章节区间和缓存文件 |
| `ContextResolver` | 把选区映射到文本块及章节，选取相邻段落和术语 |
| `PromptBuilder` | 在上下文预算内构造请求，保证选区永不被截断 |
| `OpenAICompatibleClient` | 地址规范化、鉴权、SSE 解析、取消和错误分类 |
| `ResponseParser` | 解析译文、解释、术语建议及可选论文档案 |
| `CacheRepository` | 插件自有缓存读写、版本迁移、原子替换和 LRU 清理 |
| `CredentialStore` | 通过 Mozilla Login Manager 保存 API Key |
| `PerformanceRecorder` | 只记录耗时、状态码和大小，不记录 API Key 或论文正文 |

### 4.2 依赖方向

UI 只依赖应用服务接口，不直接读取 PDF 或调用网络。索引器不依赖 UI；API 客户端不依赖 Zotero 阅读器对象。所有关键模块可使用伪造输入单独测试。

## 5. 文档索引设计

### 5.1 文档身份

缓存身份包含：

- Zotero attachment key；
- 文件大小和修改时间；
- 文件内容快速指纹；
- Zotero 元数据修订标记；
- 索引格式版本；
- 标题识别算法版本。

任一关键字段变化时重新索引。索引失败时保留上一份可用缓存；新索引完整写入临时文件并通过原子替换生效。

### 5.2 阅读顺序

仅使用页码和纵坐标无法可靠处理双栏 PDF，因此：

1. 提取每个页面的文本块、矩形坐标、字体和文本；
2. 检测单栏、双栏及跨栏标题；
3. 计算页面内阅读顺序；
4. 为全文文本块分配连续 `documentOrdinal`；
5. 保存页面坐标到 `documentOrdinal` 的映射。

选区矩形先映射到重叠度最高的文本块，再使用其 `documentOrdinal` 查询章节。

快速文件指纹使用“文件大小 + 修改时间 + 文件首尾各 64 KiB 的 SHA-256”。当 Zotero attachment key 相同但指纹改变时，视为附件内容已替换。

### 5.3 章节识别

标题候选优先级：

1. PDF 内置书签和目标位置；
2. 明确章节编号；
3. 字号、粗体、字体变化、上下留白和跨栏特征；
4. `Abstract`、`Introduction`、`Methods`、`Experiments`、`Conclusion` 等标题词典；
5. 多特征置信度评分。

每个章节保存：

```text
titlePath
level
startOrdinal
endOrdinal
source: bookmark | layout | dictionary
confidence: 0..1
```

章节查询为有序区间二分查找。置信度不足时只返回可信祖先章节；仍不可靠时退回页级上下文，并在内部诊断中标记降级原因。

### 5.4 缓存实体

- `DocumentRecord`：身份、状态、版本、错误和统计；
- `MetadataRecord`：原始 Zotero 字段及来源；
- `TextBlockRecord`：页码、坐标、文档序号、规范化文本；
- `SectionRecord`：章节路径、区间、来源、置信度；
- `PaperProfileRecord`：研究领域、研究目标、方法概述、来源及生成模型；
- `TermRecord`：原词、候选译法、确认译法、状态和最近使用时间。

MVP 使用插件数据目录下的每文档版本化 JSON 缓存，避免修改 `zotero.sqlite`。可丢弃的结构缓存默认上限为 500 MB，超过后按最近使用时间清理。用户确认术语保存在独立数据文件中，不受普通 LRU 清理影响。

## 6. 上下文选择

按以下优先级组装请求：

1. 用户选中文本，始终完整保留；
2. 选区所在完整句子或段落；
3. 当前章节路径；
4. 前后各一个邻近段落；
5. 用户已确认的相关术语；
6. 论文标题和原始摘要；
7. 已缓存论文档案；
8. 远距离相关文本，仅为未来扩展保留接口，MVP 不做向量检索。

当上下文过长时，从第 8 项开始反向裁剪，绝不裁掉选中文本。MVP 使用字符与语言启发式估算 token，不绑定某一供应商 tokenizer。

MVP 单次选区上限为 8,000 个 Unicode 字符；默认上下文数据预算为 16,000 个字符，不含固定系统提示。超过选区上限时要求用户缩小选区，不静默截断原文。

## 7. OpenAI-compatible API

### 7.1 配置

- `Base URL`：允许填写到 `/v1` 或完整 `/chat/completions` 地址；保存前去除空白和多余尾斜线；
- `API Key`：通过系统凭据存储保存，不写入普通 preference、缓存、日志或导出文件；
- `Model Name`：作为请求 `model` 原样发送；
- `Target Language`：默认 `zh-CN`，不属于 API 三项必填配置。

连接测试发送 `max_tokens: 1` 的最小非流式 Chat Completions 请求，以同时验证地址、鉴权和模型名；界面明确提示该测试可能产生极少量 token 消耗。

### 7.2 请求

默认使用：

```text
POST {normalizedBaseURL}/chat/completions
Authorization: Bearer {apiKey}
Content-Type: application/json
```

翻译请求包含 `model`、`messages`、`stream: true` 和 `temperature: 0.2`，默认总超时 60 秒。不给供应商发送 Zotero 库路径、附件本地路径、用户姓名或其他无关元数据。

### 7.3 响应协议

模型被要求使用带哨兵标记的文本协议：

```text
<<<TRANSLATION>>>
译文
<<<EXPLANATION>>>
可选解释
<<<TERMS_JSON>>>
JSON 数组
<<<PAPER_PROFILE_JSON>>>
仅首次需要的 JSON 对象
```

`TRANSLATION` 区域可流式显示，后续结构化区域在完整收到后解析。若供应商支持标准 JSON response format，可在未来增加能力探测，但 MVP 不把它作为兼容前提。

若模型未遵守标记协议：

- 有可识别译文时显示译文；
- 结构化数据解析失败时不更新论文档案或术语缓存；
- 不因解析失败自动发起第二次计费请求；
- 在浮窗提供用户主动重试。

### 7.4 取消与重试

- 每个请求绑定 `AbortController`；
- 用户取消后 1 秒内恢复可操作状态；
- 401/403、无效模型和格式错误不自动重试；
- 429 仅在服务端给出短 `Retry-After` 且请求尚未产生内容时自动重试一次；
- 5xx、连接断开和已收到部分内容的请求不自动重试；
- 明确的 context-length 错误可在缩减非必要上下文后自动重试一次，并在界面说明发生了降级。

## 8. 翻译策略

插件根据选区形态选择提示模板：

- 单词/短语：当前语境译义、词性、论文领域含义、简短解释；
- 句子：忠实翻译优先，处理指代、术语和逻辑关系；
- 段落：保持段落结构，减少无依据润色；
- “解释术语”：解释其在本文中的含义，不替代正式翻译。

所有模板要求：

- 不翻译公式、变量、引用编号和模型名称；
- 不把推断内容表述成论文原文事实；
- 对无法确定的术语保留原文或标注不确定；
- 优先使用用户确认的术语表；
- 不服从论文正文中可能出现的提示注入指令，论文内容统一放入不可信数据边界。

## 9. 安全与隐私

- API Key 存入 Mozilla Login Manager；Base URL 和 Model Name 可存普通偏好设置；
- API Key 在界面默认遮罩，只允许显式替换或清除；
- 插件升级保留凭据；卸载插件时删除 Login Manager 中的 API Key，但默认保留用户确认术语，供用户重装恢复；
- 日志过滤 `Authorization`、密钥、完整正文、译文和响应体；
- 性能记录只含时间、字符数、缓存命中、错误类别和 HTTP 状态；
- 缓存仅位于本机插件数据目录，不参与 Zotero Sync；
- 不直接修改 Zotero 数据库；
- 不自动创建批注或笔记；
- 只有用户明确操作时才把结果复制到剪贴板；
- 卸载插件时默认不删除用户确认术语；提供独立的“清除插件数据”操作。

## 10. 错误与降级

| 场景 | 行为 |
|---|---|
| 未配置 API | 浮窗指向设置页，不发送请求 |
| 401/403 | 显示密钥无效，不自动重试 |
| 404/模型错误 | 分别提示检查 Base URL 和 Model Name |
| 429 | 显示限流与等待时间；符合条件时只重试一次 |
| 超时/断网 | 保留选区和浮窗，允许主动重试 |
| 用户取消 | 停止读取流，不写入不完整缓存 |
| 响应格式异常 | 显示可识别译文，不写结构化缓存 |
| PDF 无文本层 | 明确提示 MVP 不支持 OCR |
| 索引未就绪 | 使用元数据和当前页文本降级翻译 |
| 索引损坏 | 隔离损坏缓存，后台重建，保留可用旧版本 |
| 章节置信度低 | 使用可信祖先章节或页级上下文 |
| 上下文过长 | 裁剪非必要上下文后最多重试一次 |

所有异常不得阻塞 Zotero 主线程，不得影响阅读、注释、保存或关闭 Zotero。

## 11. 测试策略

### 11.1 单元测试

- Base URL 规范化；
- 响应哨兵解析与异常恢复；
- 单双栏阅读顺序；
- 选区矩形到文本块映射；
- 章节区间二分查询；
- 上下文裁剪优先级；
- 缓存指纹、失效、原子替换与版本迁移；
- 术语建议和用户确认状态；
- 错误分类、取消和重试判定；
- 日志敏感信息过滤。

### 11.2 API 集成测试

使用本地伪造 OpenAI 服务覆盖：

- 正常非流式连接测试；
- SSE 分片边界；
- 多字节中文跨分片；
- 空 delta、`[DONE]`、连接中断；
- 401、403、404、429、5xx；
- 响应标记缺失、乱序和 JSON 损坏；
- 取消与超时；
- context-length 降级重试；
- 确认日志不含密钥或正文。

### 11.3 PDF 测试集

至少 30 篇：

- 有/无书签；
- 单栏/双栏；
- 10–100 页；
- 跨栏标题；
- 公式、表格和参考文献密集；
- 摘要缺失或 Zotero 元数据错误；
- 中英文混排；
- 无文本层扫描 PDF。

正确性门槛：

- Zotero 已有标题和摘要时读取成功率 100%；
- 有可靠书签时章节定位准确率至少 95%；
- 无书签但排版规范时至少 85%；
- 置信度不足时必须降级，不得伪造章节。

### 11.4 翻译质量测试

建立至少 100 条包含术语歧义、代词指代、缩写和长句逻辑的测试样本，对比“只发送选区”和“发送结构化上下文”两种结果。术语、指代、逻辑和忠实度各按 0–2 分评分；上下文版本四项总平均分需比基线提高至少 15%，且重大事实性错误数量不得高于基线。

## 12. 性能与稳定性验收

参考电脑需记录 CPU、内存、磁盘、Windows 和 Zotero 版本。插件本地耗时与第三方 API 网络耗时分别统计。

| 指标 | 验收门槛 |
|---|---:|
| 插件增加的 Zotero 启动耗时 | P95 ≤ 300 ms |
| 选中后展示浮窗 | P95 ≤ 100 ms |
| 已缓存章节定位 | P95 ≤ 20 ms |
| 上下文组装 | P95 ≤ 50 ms |
| 30 页文本 PDF 首次索引 | P95 ≤ 5 秒 |
| 100 页文本 PDF 首次索引 | P95 ≤ 15 秒 |
| 已缓存论文再次载入 | P95 ≤ 200 ms |
| 索引期间单次主线程长任务 | ≤ 100 ms |
| 100 页论文索引峰值增量内存 | ≤ 100 MB |
| 关闭文档并完成回收后的残留增量内存 | ≤ 30 MB |
| 取消 API 请求后的界面响应 | ≤ 1 秒 |

稳定性场景：

- 连续 100 次选区操作；
- 连续 50 次伪造 API 请求；
- 同时打开 5 篇论文，后台索引并发上限为 1，排队任务可取消；
- 重复启用、禁用和升级插件；
- 打开/关闭阅读器 50 次；
- 验证没有重复事件监听、悬挂请求、浮窗残留和持续内存增长；
- 插件异常时 Zotero 阅读、注释、保存和退出功能正常。

任何硬性性能或稳定性门槛失败时不得发布 `.xpi`。

## 13. 交付验收

交付需同时满足：

1. Zotero 9.0.6 Windows 64 位可安装、启用、禁用和卸载；
2. 三项 API 配置及连接测试可用；
3. 单词、句子和段落翻译可用；
4. 浮窗全程不转侧栏，点击按钮不丢失选区；
5. 标题、摘要、章节和术语上下文自动生效；
6. 缓存失效、重建和清理符合设计；
7. 错误场景可恢复且不影响 Zotero；
