# Zotero Context Translator 0.1.3 关闭按钮修复设计

## 问题与根因

关闭按钮位于 `.zct-titlebar` 内部。真实鼠标按下关闭按钮时，`pointerdown` 会冒泡到标题栏；现有标题栏拖动处理器不区分事件来源，立即建立拖动状态并调用 `setPointerCapture()`。后续 `pointerup`/`click` 因指针捕获可能被重定向到标题栏，关闭按钮的 `click` 处理器因此偶发或持续收不到事件。

旧回归测试把 `pointerdown` 直接派发给浮窗根元素，伪 DOM 又不实现事件冒泡，所以没有覆盖“按钮 → 标题栏 → 浮窗”的真实事件路径。

## 修复范围

采用最小交互修复，不调整已确认的视觉设计、浮窗布局、API、缓存或翻译流程：

1. 标题栏收到来自按钮或其他交互控件的 `pointerdown` 时，不建立拖动状态，也不调用 `setPointerCapture()`。
2. 浮窗根元素继续阻止 PDF 选区因交互而被取消。
3. 关闭仍由标准 `click` 触发，保留键盘激活、辅助技术语义和 `Esc` 关闭。
4. 非交互标题区域继续使用现有拖动阈值与指针捕获逻辑。

不采用 `pointerdown` 直接关闭，因为这会偏离按钮标准激活语义并增加键盘/辅助功能分支；不移动关闭按钮，因为根因不在布局。

## 回归测试

新增测试必须先在现有实现上失败，并证明：

- 关闭按钮的 `pointerdown` 不调用标题栏的 `setPointerCapture()`，随后第一次 `click` 调用一次关闭处理器；
- 普通标题区域仍调用 `setPointerCapture()` 并可进入拖动；
- 既有 `Esc`、20 次首击关闭、模式按钮与选区保持测试继续通过。

隔离 Zotero 9.0.6 验收使用真实 Reader `customEvent` 路径，连续执行至少 20 次完整 `pointerdown` → `pointerup` → `click` 序列，要求首击关闭 20/20、原 PDF 选区不丢失、普通标题区域仍可拖动。

## 版本与交付

- 版本提升到 `0.1.3`，避免用户安装同版本 XPI 时产生缓存或覆盖歧义。
- 重新运行全部测试、构建 XPI、审计包内容并更新安装说明与验收报告。
- 0.1.2 保留不覆盖；0.1.3 作为最终推荐安装包。
