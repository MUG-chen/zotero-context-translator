# Zotero Context Translator 0.1.2：可靠 API 与学术阅读卡片设计

## 目标

修复 0.1.1 中两个直接影响日常使用的问题：OpenAI 兼容流式请求被固定 60 秒总计时器误杀、临时 5xx 无重试；以及浮窗视觉层级薄弱、首次嵌入时关闭按钮可能因 DOM 移动而丢失点击。

保持既有产品原则：窗口浮动、不注入固定侧栏、不取消 PDF 选区、后台结构索引不主动调用 API、只要求 OpenAI Chat Completions 兼容接口。

## 已确认的根因

### 超时与服务错误

- `OpenAICompatibleClient` 当前从 `fetch` 开始到 SSE 完全结束共用一个 60 秒绝对计时器；即使流持续返回，60 秒到达后仍会中断。
- 所有 HTTP 5xx 都立即转换为通用 `TransportError`，且现有测试明确禁止重试服务器错误，因此一次 502/503/504 抖动就直接暴露给用户。
- 错误界面只显示英文异常文本，丢失 HTTP 状态、尝试次数和下一步操作。
- DeepSeek 官方服务在排队时可发送 SSE `: keep-alive`，并建议 503 后短暂等待重试；V4 默认思考模式还可能延迟正式译文。参考：[错误码](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes/)、[请求保活机制](https://api-docs.deepseek.com/zh-cn/quick_start/rate_limit)。

### 关闭按钮

初始窗口属于 Zotero 原生选区弹层。当前根节点在任意 `pointerdown` 时立即移动到 `document.body`，包括关闭按钮按下的时刻。节点在 `pointerdown` 与 `click` 之间换父级，后续点击可能丢失；窗口已脱离后则正常，因而表现为间歇性失效。

## 方案选择

视觉采用“学术阅读卡片”，不采用信息不足的极简工具提示，也不采用遮挡论文的迷你工作台。网络采用通用 OpenAI 兼容恢复策略，不根据 `api.deepseek.com` 自动注入厂商私有参数。

## 网络可靠性设计

### 计时阶段

请求分为三个阶段，每个计时器都服从同一个用户取消信号：

1. 建连阶段：沿用平台 `fetch`；同步配置错误立即失败。
2. 首次模型事件阶段：从发送请求起最多等待 90 秒。SSE 注释和空行不算模型事件；首个合法 JSON SSE 事件（包括 `reasoning_content`）表示模型已经开始工作。
3. 活动流阶段：不再设置总时长上限。每次收到网络数据块或合法 SSE 事件都重置 45 秒静默计时器；只有连续静默 45 秒才中断。

连接测试仍使用短请求，不进入翻译重试状态机。

### 自动重试

- HTTP 502、503、504：在没有模型事件时自动重试。
- HTTP 429：优先解析 `Retry-After` 秒数或 HTTP 日期；等待不超过 15 秒时自动重试。
- 响应前的临时网络错误：若不是用户取消或超时，允许重试。
- 最多三次请求，即最多两次重试；默认递增等待约 800 ms、2 s，测试中通过注入的睡眠函数消除实际等待。
- 一旦收到任一模型事件，不自动重试，避免重复计费或重复输出；保留已经显示的译文，并提供手动重试。
- 401/402/403/404、参数错误、上下文超限、用户取消不重试。

API 客户端通过 `onProgress` 回调发出 `waiting`、`reasoning`、`retrying` 和 `streaming` 事件。事件只包含阶段、HTTP 状态、当前尝试和总尝试，不包含 API Key、论文正文或完整请求地址。

### 错误呈现

错误映射为中文用户消息，例如“服务暂时繁忙”“等待模型响应超时”“流式响应中断”。错误卡片显示安全的细节行，如 `HTTP 503 · 已尝试 3 次`，并提供“重新尝试”。底层原始错误仍通过 Zotero 日志记录，但不得记录 Authorization、请求正文或含凭据的 URL。

## 学术阅读卡片设计

### 布局

- 目标宽度 440 px；小视口使用 `min(440px, calc(100vw - 32px))`。
- 圆角 14 px、细边框、两级阴影和 Zotero 蓝单一强调色。
- 最大高度为视口减 32 px；标题栏、模式选择和底部上下文提示固定，正文区域独立滚动。
- 浅色与深色模式均使用语义颜色变量，正文对比度不低于 WCAG AA。

结构从上到下为：标题与状态、原文预览、分段模式选择、状态/错误区域、译文、说明、上下文范围提示。

### 内容层级

- 原文预览默认三行，带渐隐与“展开/收起”，不再无提示裁切。
- 四个模式使用分段选择器；当前模式以蓝色底和白字突出。
- 译文使用主字号和宽松行高；说明进入独立浅色次级卡片。
- 结果区域提供复制按钮；复制成功以短暂状态反馈呈现。
- 加载状态显示轻量旋转指示、明确阶段文字和重试次数，不用空白等待。
- 错误状态使用低刺激红色图标/边框，不把整张卡片染红。

### 关闭、脱离与拖动

- 关闭按钮使用内联 SVG，点击目标至少 36×36 px，并支持鼠标、触控、Enter、Space 和 Escape。
- 根节点不再对所有 `pointerdown` 立即脱离。
- 关闭按钮的操作永远不触发脱离；首次点击直接关闭。
- 模式按钮先完成 `click` 处理，再把同一窗口脱离到 Reader 文档根部，确保事件不会因换父级丢失。
- 标题栏只有移动超过 4 px 后才开始拖动和脱离；普通点击标题栏不改变 DOM。
- 窗口移动后继续限制在视口边缘 12 px 内。

## 状态与组件边界

- `OpenAICompatibleClient` 只负责请求阶段、重试分类、SSE 活动和安全进度事件。
- `SelectionState` 增加非敏感的 `progress`、`mode`、`attempt` 信息，并保留现有请求 ID 防止旧响应复活。
- `TranslatorPlugin` 保存最后一次模式，接收 API 进度并转发到同一 `FloatingView`；错误卡片的手动重试复用当前选区和模式，重新解析最新缓存上下文。
- `FloatingView` 只渲染状态和分发 `translate`、`retry`、`copy`、`close` 事件，不包含 API 逻辑。

## 安全与兼容性

- 插件 ID、首选项键、Login Manager realm 和缓存版本保持不变，0.1.1 升级到 0.1.2 时保留设置、密钥和论文缓存。
- 不增加第三方 UI 库、远程字体、遥测或厂商专有 API 参数。
- 自动重试只发生在无模型输出阶段；用户取消立即终止当前等待和后续重试。
- 复制操作仅复制译文，不复制论文上下文、错误诊断或 API 信息。

## 测试与验收

### 自动化 TDD

- 先写失败测试验证：持续活动的长流不会被总时长误杀；只有 keep-alive 的请求在 90 秒时失败；模型开始后静默 45 秒失败。
- 依次验证 502/503/504 后恢复、429 `Retry-After`、响应前网络错误，以及模型事件后/认证错误/用户取消不重试。
- 验证进度事件顺序、尝试次数和错误安全字段。
- 初始嵌入状态下连续 20 次首次关闭均成功；模式 `click` 在脱离前执行；标题栏未跨 4 px 不脱离。
- 验证原文展开、复制、手动重试、键盘关闭、独立译文与说明区域。
- 100 次挂载、状态切换、关闭后只允许一个浮窗且无监听器残留。

### Zotero 9.0.6 实机

- 在真实 Reader iframe 事件路径中确认 PDF 选区保持、浮窗不进入侧栏。
- 本机模拟 OpenAI 服务制造慢首包、503 后恢复、长活动流和流中断；不使用用户 DeepSeek Key。
- 浅色、深色和窄视口做截图检查；文本不得溢出，按钮不得挤压，滚动只发生在内容区。
- 重复首次关闭 20 次，成功率必须为 100%。
- 记录挂载耗时和 100 次生命周期稳定性；不得降低现有性能门槛。
