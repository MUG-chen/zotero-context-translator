# Zotero Context Translator 验收规范

## 发布原则

以下任一必需项失败，均不得把构建标记为正式可用。自动化测试不能替代 Zotero Reader 实机验证。

## 自动化门禁

在仓库根目录运行：

```powershell
npm test
npm run build
```

必须满足：

- 所有 Node 测试通过。
- `outputs/zotero-context-translator-0.2.0.xpi` 的根目录包含 `manifest.json`、`bootstrap.js` 和 `prefs.js`。
- XPI 不包含 API Key、缓存、日志、测试、`work/` 或用户论文。
- 401/403、用户取消和首个模型事件后的流中断不重试；尚未收到模型事件时，502/503/504 或临时连接错误最多重试两次；短暂 429 遵守不超过 15 秒的 `Retry-After`。
- 在 429 或临时 5xx 的退避等待中取消，应在 1 秒内结束，且不得再发出下一次请求。
- 首个有效模型事件必须在 90 秒内到达；SSE keep-alive 不算模型事件。模型开始后不设总时长上限，连续静默 45 秒才中断。
- `reasoning_content` 只用于显示“模型正在分析论文上下文”状态，不得展示或记录思维内容。
- 用户取消信号在整个 SSE 生命周期内有效。
- 响应元数据损坏时保留可见译文，且不写入损坏的结构化字段。
- 启动中途失败时回滚 Reader 监听器和首选项面板；结构索引失败或超时不得调用 API。
- 当前段落必须由视觉行重建，且不得跨页、跨栏或越过章节标题。
- 设置页必须通过 Zotero 片段的 `showing` 事件初始化，并在重复显示时只绑定一次按钮。
- Reader 浮窗必须通过 iframe 发出的真实 `customEvent` 跨域路径验证；直接调用 `_dispatchEvent` 不能作为唯一验收路径。
- 每个有效选区只能在 Zotero 原生标注栏下方显示一个紧凑的“译 翻译”触发器；不得显示完整翻译卡片或旧模式控件。
- 触发器的 `pointerdown` 必须保留 PDF 选区和原生标注操作；连续点击或 Zotero 重复渲染同一选区不得产生重复请求。
- 选择文本只启动本地索引，不得调用 API；点击一次触发器必须只产生一次统一的上下文翻译请求，并立即移除触发器。
- 点击触发器后，活动卡片必须挂载在 Reader 持久浮层中并从触发器下方展开；不得依赖原生选区弹层的 DOM 生命周期，也不得绘制旧选区覆盖层。
- 活动卡片不得显示第二个“翻译”主按钮；`loading`、流式输出、`result` 和 `error` 必须在同一卡片中更新。
- 同一论文中的普通新选区不得取消活动请求、清空状态或销毁活动卡片；只有点击新触发器才可取消旧请求并在原卡片中替换翻译。
- 跨附件产生有效选区时必须关闭旧活动卡片；同一时刻最多有一个活动卡片和一个临时触发器。
- 替换翻译时必须立即显示新的冻结原文并清除旧译文；错误状态必须保留冻结选区并允许明确重试。
- 卡片默认宽度必须为 380px、自动适配最大高度为 520px、基础字体为 12px、译文字体为 14px；卡片按钮点击目标不得小于 36px。
- 活动卡片从创建起即可拖动和从右下角缩放，最小尺寸为 320×240px；拖动必须从当前可见位置开始且只能产生一个卡片实例。
- 新翻译必须保留卡片位置和宽度；用户手动设置的高度继续保留，自动适配高度恢复紧凑状态后再随新结果增长。
- 学术阅读卡片必须分离原文、译文、说明和错误区域，并验证原文展开、译文复制、手动重试、深色模式和窄视口。
- 长译文、展开原文或 Reader 缩小时，卡片标题栏必须保持可找回；自动适配高度取 520px 与 Reader 高度减 24px 的较小值，超出内容在正文区域独立滚动。
- 复制成功时只写入译文；剪贴板不可用或写入失败时必须显示“复制失败”，不得误报成功。
- 100 次选区、50 次翻译、5 个文档后最多只有一个活动卡片和一个临时触发器，关闭后无监听器和请求泄漏。

## 性能门槛

| 指标 | 发布门槛 |
|---|---:|
| 插件新增启动时间 P95 | ≤ 300 ms |
| 选区触发器出现时间 P95 | ≤ 50 ms |
| 活动卡片出现时间 P95 | ≤ 100 ms |
| 缓存章节查找 P95 | ≤ 20 ms |
| 上下文构建 P95 | ≤ 50 ms |
| 30 页结构索引 | ≤ 5 s |
| 100 页结构索引 | ≤ 15 s |
| 缓存重新加载 | ≤ 200 ms |
| 主线程单任务 | ≤ 100 ms |
| 100 页峰值新增内存 | ≤ 100 MB |
| 关闭后残留新增内存 | ≤ 30 MB |
| 取消到停止回调 | ≤ 1 s |

Node 合成基准用于验证算法回归；PDF.js 提取时间、主线程长任务和内存必须在 Zotero 9.0.6 实机测量。

## Zotero 9.0.6 实机门禁

使用独立 profile 和独立空数据目录：

1. 安装 XPI，验证启用、禁用、重启、卸载和再次安装。
2. 确认设置页字段完整；API Key 输入为掩码；未点击“测试连接”时无网络请求。
3. 打开单栏、双栏、元数据缺失和扫描版 PDF。
4. 选择单词、句子和段落，记录 Reader 事件的字段名和类型，不记录论文文本。
5. 验证原生标注栏下方只出现一个紧凑触发器；划线后请求数为 0，点击一次后请求数为 1，按钮点击不取消选区或阻止高亮、下划线等原生操作。
6. 验证活动卡片从触发器下方展开并独立于原生标注栏；加载中和完成后连续选择、标注同一论文的其他文字，卡片与请求均不得消失或中断。
7. 验证 380px 紧凑默认宽度和字体清晰可读；分别用短句、长段落和长译文确认 520px 自动适配上限与内部滚动。
8. 验证拖动始终从当前位置开始、只存在一个活动卡片；从右下角缩放到最小尺寸，再触发新翻译，确认位置、宽度和用户设置高度得到保留。
9. 验证原文展开、译文复制、错误重试、键盘焦点、`Esc`、点击新触发器替换，以及跨附件选区清理。
10. 关闭 Reader 标签页，确认卡片随页面卸载且不残留文档监听器或 `ResizeObserver`。
11. 首次打开建立结构索引；第二次打开命中缓存；修改附件指纹后重新索引。
12. 对扫描版 PDF 显示明确的不支持信息，且不调用 API。
13. 使用本机 OpenAI 兼容模拟服务验证慢首包、keep-alive、503 后恢复、活动长流和部分流中断；不得使用用户真实 API Key。

## 验收语料

- 合成布局样例：单栏文本片段、窄栏距双栏、三栏提示、通栏块、行内摘要以及 30/100 页索引负载，用于可重复算法基线。
- 用户明确授权的 21 页 USENIX Security 论文：真实双栏、封面页、可选中文本层、PDF 标题元数据为空，用于标题/摘要回退、章节路径和缓存命中验证。论文正文不得进入仓库或发布包。
- 扫描版占位样本：用于确认 OCR 不支持提示。

## 记录模板

最终验收报告至少记录：

- Zotero、Windows、CPU、内存、Node 版本
- XPI SHA-256
- 自动化测试总数和结果
- 每项性能实测值、P95 采样数和通过/失败
- 每种语料的索引时间、缓存加载时间、章节路径和回退原因
- 网络请求次数、取消时间和错误策略
- 已知限制及未通过项
